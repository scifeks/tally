# PHP framework defaults patterns

Vulnerable-vs-safe snippets for PHP framework default settings the
`misconfig.framework_defaults` scanner recognizes. When multiple safe
forms exist, the canonical one is shown first.

## Laravel APP_DEBUG

### Vulnerable

```php
// .env (production)
APP_DEBUG=true

// or in config/app.php
'debug' => env('APP_DEBUG', true),

// or hardcoded
'debug' => true,
```

### Safe

```php
// .env (production)
APP_DEBUG=false

// or in config/app.php
'debug' => env('APP_DEBUG', false),
```

Set `APP_DEBUG=false` in the production `.env` file. Load the setting from
the environment with a safe default. Never set `debug => true` in config
arrays for production deployments.

## Laravel APP_KEY

### Vulnerable

```php
// .env (production)
APP_KEY=base64:SomeDefaultKeyHere==

// or empty
APP_KEY=

// or hardcoded in config
'key' => 'base64:insecure-key',
```

### Safe

```php
// .env (production)
APP_KEY=base64:<generated-key>

// Generated by: php artisan key:generate
// Store the output in .env
```

Generate a unique `APP_KEY` with `php artisan key:generate` and store it
in the production `.env` file. Never rely on default or base64-encoded
tutorial values.

## Laravel APP_ENV

### Vulnerable

```php
// .env (production)
APP_ENV=local

// or
APP_ENV=development
```

### Safe

```php
// .env (production)
APP_ENV=production
```

Set `APP_ENV=production` in the production `.env` file. This controls
configuration caching and error reporting behavior.

## Symfony APP_ENV

### Vulnerable

```php
// .env (production)
APP_ENV=dev

// or hardcoded in services.yaml
parameters:
  app.env: dev
```

### Safe

```php
// .env (production)
APP_ENV=prod

// or
APP_ENV=production
```

Set `APP_ENV=prod` or `APP_ENV=production` in the production `.env` file.
Never set `APP_ENV=dev` in production deployments.

## Symfony APP_DEBUG

### Vulnerable

```php
// .env (production)
APP_DEBUG=1

// or
APP_DEBUG=true
```

### Safe

```php
// .env (production)
APP_DEBUG=0

// or
APP_DEBUG=false
```

Set `APP_DEBUG=0` in the production `.env` file. Disable debug mode in
production to prevent stack trace exposure.

## Symfony APP_SECRET

### Vulnerable

```php
// .env (production)
APP_SECRET=ChangeMe

// or empty
APP_SECRET=

// or a common default
APP_SECRET=default-secret
```

### Safe

```php
// .env (production)
APP_SECRET=$(php -r 'echo bin2hex(random_bytes(16));')

// or load from a secure environment variable
APP_SECRET=${SYMFONY_SECRET}
```

Generate a unique `APP_SECRET` with sufficient entropy and store it in
the production `.env` file or a secure environment variable. Never use
default or empty values.

## WordPress WP_DEBUG

### Vulnerable

```php
// wp-config.php (production)
define('WP_DEBUG', true);
define('WP_DEBUG_LOG', true);
define('WP_DEBUG_DISPLAY', true);
```

### Safe

```php
// wp-config.php (production)
define('WP_DEBUG', false);
define('WP_DEBUG_LOG', false);
define('WP_DEBUG_DISPLAY', false);
```

Set `WP_DEBUG` to false in production deployments. Disable debug logging
and debug output to prevent sensitive information exposure.
